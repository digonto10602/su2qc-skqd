# 10 — L5 fix (2026-09-14): CUDA-Q 0.15.1 `SampleResult` API in the convention tests
executor: executor-opus   effort: high
time budget: 30 min   machine: laptop (CPU: `--target qpp-cpu`; the `nvidia` target aborts on this GPU)

> Written by planner-fable after `python scripts/run_gate.py L5 --target qpp-cpu` exited with a traceback
> before any criterion was evaluated.

## Failure
- `AttributeError: 'cudaq.mlir._mlir_libs._quakeDialects.cudaq_runtime.SampleResult' object has no attribute
  'keys'` raised in `scripts/laptop_L5_cudaq_check.py:string_order_test` (line `list(cudaq.sample(...).keys())[0]`);
  the same pattern is in `endian_test`.  Exit code 1 after 2 s, no `validation/L5.json`.
- Environment: cuda-quantum-cu12 0.15.1 (pip wheel), custatevec-cu12 1.13.1, cutensornet-cu12 2.12.2.  The
  `nvidia` target prints `GPU not supported. This simulator requires a GPU with compute capability 7.0 or
  later.` and aborts the process (the GTX 1060 Max-Q is compute capability 6.1).  `qpp-cpu` works (Bell state
  sampled correctly).  `@cudaq.kernel` functions must live in a `.py` file, not stdin.

## Diagnosis
`cudaq.SampleResult` in 0.15.1 is not a dict: it has `items()`, iteration over bitstrings, `most_probable()`,
`count(bitstring)`, `get_register_counts`, but no `keys()`.  The L5 script was written without a CUDA-Q
installation (the build sandbox had no PyPI access) and used the dict idiom in the two convention tests.
`src/skqd/circuits_cudaq.py:sample` uses `res.items()`, which exists; check it once the script runs.

## Fix
`scripts/laptop_L5_cudaq_check.py`: in `string_order_test` and `endian_test`, obtain the (single) observed
bitstring with `cudaq.sample(...).most_probable()` (or `next(iter(result))`) instead of `.keys()`.  Keep the
semantics: 10 shots of a deterministic circuit give one bitstring; the tests compare bitstrings exactly as
before.  If any further CUDA-Q API mismatch appears while the script runs (in the gate script or in
`src/skqd/circuits_cudaq.py`: `register_operation`, kernel source generation, `sample`), fix the API use
only — never the convention logic (`_maybe_permute`, `BIG_ENDIAN`, `qubit0_first`) unless the convention
test itself tells you to flip `BIG_ENDIAN`, in which case make the flipped value the module default as the
prompt 05 says and note it.
